# Архитектура проекта — Colony Simulation Game (Godot 4.7 C# / .NET 8)
=========================================================================

## Обзор проекта
Жанр: Колония / Стратегия непрямого контроля (до 10 000+ агентов).
Движок: Godot Engine 4.x, .NET / C#, рендер: gl_compatibility (Forward compatibility).
Карта: 512×512 тайлов (64px), с поддержкой бесконечного мира за кромкой острова.
Мировая карта-обзорка: 2048×1024 регионов по 512×512 клеток (см. КОНСТАНТЫ МИРА ниже).
Архитектурный паттерн: SoA (Structure of Arrays) для данных агентов, выделенный фоновый поток симуляции, GPU instancing (MultiMeshInstance2D) для массового рендеринга.

### src/core/common/GameProfiler.cs

### src/core/common/ProfilerLogService.cs
Сервис логирования профайлера — Accumulate/BuildReport, запись CSV, снапшоты в очередь. Связан с GameProfiler и PerformanceOverlay.

### src/core/common/SimEvents.cs
Единый канал событий для симуляции: иерархические скоупы (ThreadLocal Stack), tick-trace, счётчики ошибок, аллокаций, batched samples. Используется GameProfiler, GameProfiler.ScopeSample(), FlowFieldManager, HotPathProfiler. Буферизирует данные для PerformanceOverlay и лог-сервиса.

### src/core/common/ToolRequirement.cs
Перечисление требований инструментов к ресурсам/зданям. Используется BlueprintManager, Handler'ами, инструментами.

### src/simulation/GameSpeed.cs

### src/core/common/ResourceRef.cs
Референс ресурсов (UID-based). Используется в рендерах для загрузки текстур.

### src/simulation/WorldTime.cs

Используется DayNightCycle, TimeManager, AgentSimulationThread. ПРИМЕЧАНИЕ: файл лежит в src/simulation/, а не в src/core/common/ как было задокументировано ранее.

### src/core/common/ResourceTypes.cs
Типы ресурсов экономики (ResourceType enum). Legacy/расширяемая система.

SRC/CORE/WORLD — Карта, тайлы, генерация
===============================================================================

### src/core/world/TileType.cs
Основные типы тайлов: Grass, Water, Mountain. Используется всеми менеджерами для проходимости и строительства. IsTileBlocked в AgentMovementService, CanPlace в Tool'ах.

### src/core/world/BiomeType.cs
Тип биомов для бесконечного мира (за пределами острова).

### src/core/world/BiomeMapper.cs
Маппинг биомов по координатам мира. Используется WorldCellQuery при генерации мирового террейна.

### src/core/world/MapData.cs
Структурированные данные карты: Ground[], TreeOnGrass[], StoneOnGrass[], Fertility[], Humidity[], BiomeSeed, LakeCount, RiverBranchCount, LandConnectivity. Создается MapGenerator.Generate/GenerateOnce, передаётся в MapRenderer.StartAsync() и AgentSimulationThread.Start().

### src/core/world/MapGenerator.cs
Генератор карты: fBm высот (4-5 октав, scale 90-140), island-falloff, порог воды 0.38-0.42, река downhill, связность >=92%, лес Poisson-disc, старт-поляна R12. Генерирует Ground/TreeOnGrass/Stones/Fertility/Humidity. Retry до 4 раз. Использует NoiseGenerator, RiverGenerator. ПРИМЕЧАНИЕ: на диске есть только MapGenerator.cs.uid, физического .cs файла нет — возможно удалён или включён в другой модуль.

### src/core/world/NoiseGenerator.cs
Шум Perlin/simplex для генерации карт высот, влажности, плодородия. Используется MapGenerator.

### src/core/world/RiverGenerator.cs
Карving реки: downhill from heightMap, source at top, mouth at edge/lake, width 1-2, up to 2 tributaries. Modifies Ground array. Вызывается MapGenerator.GenerateOnce. ПРИМЕЧАНИЕ: на диске только .uid файл — физический .cs отсутствует.

### src/core/world/GridHelper.cs
Utility функции для сетки: TryFindAdjacentWalkable, TryFindNearestFreeTile, BoundsSafe checks. Используется MovementService, JobBroker, GridHelper.

### src/core/world/BuildingType.cs
Типы зданий: WoodWall (15 logs), WorkTable (25 logs). blueprintManager AddBatch uses these types, Handler'ами for construction.

### src/core/world/WallTileHelper.cs
Автотайлинг стен: 16 mask→atlas mapping (Up=1, Right=2, Down=4, Left=8). Used by WallBuildManager.Add/Remove, MapRenderer.wall layer cell updates. ПРИМЕЧАНИЕ: на диске только .uid — физический .cs отсутствует.

### src/core/world/MountainTileHelper.cs
Автотайлинг гор: аналогично стенам (16 клеток 4×4 atlas). Горы = blocked (как стены), not water-slow. Created by MapRenderer after generate mountains > threshold. ПРИМЕЧАНИЕ: на диске только .uid — физический .cs отсутствует.

### src/core/world/HumidityMap.cs
Влажность почвы: flat int[] double-buffered, тик every 30 game seconds (~6 ticks per minute). Forestry slightly humidifies, farming dries out. Used by FarmJobManager, CropGrowthManager (growth rate influenced by moisture).

### src/core/world/FertilityMap.cs
Плодородие: max 200 (black soil), flat int[] double-buffered, тик every 60 game minutes. Forest fertilizes, garden depletes. Used by FarmJobManager when checking plot quality.

### src/core/world/FarmYield.cs
Выход фермерства: Grain per tile based on fertility/moisture stages. Used in CropGrowthManager.HarvestCrop.

### src/core/world/streaming/generation/WorldCoordinates.cs
Мировая координатная система: TileToChunk()/ChunkToLocalForTile(), floor division. Used everywhere across infinite world module.

### src/core/world/streaming/generation/WorldChunk.cs
One chunk (64×64 tiles): terrain cell enum, moisture/forest flags, delta mutations list. No Godot dependencies. Persisted via WorldChunkCodec. Created by ChunkWindowPlanner requests, filled by ParallelChunkGenerator or GpuChunkGenerator.

### src/core/world/streaming/generation/GeneratedCell.cs
Single cell metadata: terrain + moisture/forest flags. Lightweight struct used by WorldChunk and generator pipelines.

### src/core/world/streaming/generation/WorldChunkGenerator.cs
CPU генератор чанков: noise-based terrain, moisture, forest placement for a single chunk. Called by ChunkWindowPlanner. Uses NoiseGenerator patterns. Zero alloc in hot path.

### src/core/world/streaming/generation/ParallelChunkGenerator.cs
Multi-threaded chunk generation: parallel per-tile noise evaluation using ThreadPool. Faster than sequential.

### src/core/world/streaming/generation/GpuChunkGenerator.cs
Compute shader variant: uses RenderingDevice compute pipeline (chunk_gen_compute.compute). Not active in production (gl_compatibility mode lacks RenderingDevice access). Present as future option.

### src/core/world/streaming/generation/WorldFeatureGenerator.cs
Forest planting (Poisson disc), stone distribution, lake limits enforcement. Post-processing step after base terrain. Shared between island and streaming world.

### src/core/world/streaming/generation/WorldRegions.cs   (ОБНОВЛЕНО — источник истины констант)
namespace Game.Core.WorldStreaming. Константы: WorldRegionsX=2048, WorldRegionsY=1024, RegionSize=512, ChunkCells=64, TilesPerRegionAxis=RegionSize/ChunkCells=8. Методы FloorDiv/FloorMod (корректны для отрицательных), RegionForCell, LocalForCell, RegionOrigin, RegionBounds, IsInsideWorld. ВЫНЕСЕННЫЕ ЗИСИМОСТИ: WorldCell/WorldRect объявлены в том же namespace Game.Core.WorldStreaming (подтверждено диагностикой), поэтому WorldRegions.cs компилируется без внешних using; compat-файл WorldRegionsCompatTypes.cs НЕ нужен (exists=False). ВАЖНО: раньше в этом файле был комментарий «1024×2048 регионов» — это ИНВЕРСИЯ относительно целевой схемы заказчика (2048×1024); истинные значения констант — X=2048, Y=1024. Перед использованием любых consumer-ов сверять оси по этому источнику истины.

### src/core/world/streaming/generation/RegionKey.cs   (НОВЫЙ ФАЙЛ)
namespace Game.Core.WorldStreaming; public readonly record struct RegionKey(long X, long Y); Вынесен в отдельный файл, чтобы ошибка компиляции WorldRegions.cs не каскадила CS0246 по всему проекту (реальный инцидент: пока WorldRegions.cs не компилировался, RegionKey «исчезал» для Main.cs/RegionTraits.cs/WorldMapOverlay.cs).

### src/core/world/streaming/generation/RegionTraits.cs
Trait per region: biome seed, elevation profile. Influences terrain generation parameters. Используется WorldMapOverlay.BuildPixels и WorldMapTileMapper.PopulateFromChunks (через RegionTraitProvider.Sample/SampleBlended).

### src/core/world/streaming/generation/WorldFeatures.cs
Collection of feature data: forest density, stone clusters, lake basins. Serialized into WorldChunkStore.

### src/core/world/streaming/generation/WorldChunkGeneratorTiming.cs
Контроллер таймингов генерации чанков: регулирует частоту вызовов ParallelChunkGenerator/WorldChunkGenerator, предотвращает перегрузку CPU при быстрой камере. Использует adaptive scheduling. НОВЫЙ ФАЙЛ.

### src/core/world/streaming/runtime/WorldChunkStreamer.cs
Main streaming controller: loads/unloads chunks around camera viewport. Coordinates with ChunkWindowPlanner. Exposes IWorldCellSource API to tools and agents.

### src/core/world/streaming/runtime/ChunkWindowPlanner.cs
Adaptive window (3..16 chunks side): budget-based load/unload decisions. Balances loading budget against frame time. Avoids unloading too aggressively near camera. Tracks Desired/Entered/Exited chunk states.

### src/core/world/streaming/storage/WorldChunkStore.cs
Persistent storage backend: reads/writes .res files to user://infinite_world_lab_cache/. Manages chunk UID cache. Used by WorldSaveCoordinator.

### src/core/world/streaming/storage/WorldChunkCodec.cs
Serialization/deserialization: converts WorldChunk ↔ bytes for disk storage. Deterministic format versioned by WorldGeneratorVersion.

### src/core/world/streaming/storage/WorldChunkDeltaCodec.cs
Delta encoding: only changed cells are serialized (WorldChunkDelta). Much smaller payload than full chunks. Used by WorldSaveCoordinator for incremental saves.

### src/core/world/streaming/storage/WorldManifestStore.cs
Manifest of stored chunks: tracks which chunk keys exist on disk. Used during load/validation/recovery.

### src/core/world/streaming/storage/WorldSaveMetadata.cs
Version + seed info for saved worlds. Ensures consistency between generators and loaded data.

### src/core/world/streaming/coordinator/WorldSaveCoordinator.cs
Batch save coordinator: collects pending deltas, writes asynchronously to disk. Prevents main thread stalls. Handles concurrent save attempts safely.

### src/core/world/streaming/integration/StreamingWorldManager.cs
Public API surface for tools and AI workers: Open(), CanPlace(x,y), IsBlocked(x,y), TryPlaceBlock(x,y,kind), TryRemoveBlock(x,y,kind). Wraps ChunkStreamer + SaveCoordinator. Connects to tool placement pass.

### src/core/world/streaming/integration/IWorldCellSource.cs
Interface for terrain/moisture queries at arbitrary world coordinates. Implemented by StreamingWorldView. Used by WorldGameRules, PlacementPass, and offline simulation.

### src/core/world/streaming/integration/IBlockWorld.cs
Interface for block/mutation operations: add/remove walls, buildings, stockpiles, crops as persistent deltas.

### src/core/world/streaming/integration/IWallWorld.cs

### src/core/world/streaming/integration/ChunkMutations.cs

SRC/SIMULATION — Игровая симуляция (фоновый поток)

### src/simulation/AgentSimulationThread.cs
Центральная симуляция (Task.Run background thread). Фиксированный шаг 0.05с. Цикл: accumulator += realDelta × speed, max 5 substeps/iteration. Three phases per step: Phase1 (ParallelMove — Pathfinding + MoveTowards), Phase2_Dispatch (Jobs), Phase3a_ParallelBookkeeping (needs update), Phase3b_SequentialCommit (spatial grid rebuild + handler commits). GameTimeSeconds accumulates real sim time. Pushes snapshot to PositionQueue ConcurrentQueue. Sleep management: Sleep(0) hot, Sleep(1) cold at high speeds. Handles humidity/fertility timers. Contains AgentSimTickGate static volatile counter.

### src/simulation/TimeManager.cs
Node-based timer: SyncGameTime(float) throttled at 10Hz from Main._Process. Public properties: GameTimeSeconds, TimeOfDaySeconds, DayNumber, CurrentSpeed. Triggers OnSpeedChanged events. Connected to AgentSimulationThread.IsPaused, SpeedMultiplier. Used by HUDController, DayNightCycle, HUD buttons.

### src/simulation/SimulationContext.cs
Shared read-only context passed to agents: Ground array, TreeOnGrass, SolidWalls, Walkable mask, AgentSpatialGrid, AgentMovementService, Random instance, TileSize, MapWidth/Height. Populated once at Start(), immutable thereafter (except walls update triggers Invalidate).

### src/simulation/DynamicWorkBalancer.cs
Existing dynamic work balancer: atomic cursor (Interlocked.Add), adaptive batch size 32-512 via EMA, ThreadLocal<ThreadState>, records balance snapshots. Currently acts as facade delegating to DynamicWorkScheduler methods. Planned replacement: AdaptivePartitioner + WorkStealingQueue (see PLAN.md §4).

### src/simulation/ParallelRng.cs
Parallel-safe RNG: [ThreadStatic] XorShift implementation. Replaces Random.Shared contention in parallel loops. Used throughout simulation worker bodies.

### src/simulation/scheduling/IDynamicWorkScheduler.cs
Interface for dynamic work scheduler: ForEach(int count, Action<int> body), ForEachRange, ForEachSplittable(int count, Action<int,int,WorkQuantum> body), GetStats(), Reset(). Designed for zero-allocation per-element dispatch.

### src/simulation/scheduling/WorkItem.cs
Zero-alloc struct: Start, Count, CostHint, WorkKind(Fast/Heavy). Passed by value to queues/deques.

### src/simulation/scheduling/WorkQuantum.cs
Cooperative quantum descriptor: DeadlineTicks (Stopwatch threshold), YieldEveryN elements checked interval. Body checks ShouldYield(token) every N items to split long tasks.

### src/simulation/scheduling/AdaptivePartitioner.cs
OrderablePartitioner for Parallel.ForEach: SupportsDynamicPartitions=true, cut [0,count) into variable-size batches based on cost hints. Heavy-kind starts smaller (minBatch), fast-kind starts larger.

### src/simulation/scheduling/WorkStealingQueue.cs
Lock-free Chase-Lev deque: per-worker ThreadLocal queue. Owner pushes/pops LIFO at bottom, thieves steal-half FIFO from top. Used when central cursor empties but other threads still running.

### src/simulation/scheduling/LoadMonitor.cs
EWMA-based phase imbalance measurement: RecordWorkerBatch(workerId, batchMs, batchSize), EndPhase(wallMs, cpuMs, DOP), returns SchedulerStats { ImbalancePct, MaxBatchMs, EmaBatchMs, StragglerCount }. Published once per phase via GameProfiler.RecordPhaseBalance.

### src/simulation/scheduling/DynamicWorkScheduler.cs
Default implementation: Static Shared singleton. Combines central cursor + per-worker deque + LoadMonitor. Provides forward-compatibility facade over DynamicWorkBalancer.

### src/simulation/scheduling/WorkStealingQueue.cs
Deque implementation: T[] buffer, volatile top/bottom indices, masked ring buffer, Interlocked.CompareExchange for CAS operations. Bounded capacity (1024 default), fallback to global cursor on overflow.

### src/simulation/agents/AgentDataPool.cs
SoA agent pool: flat arrays for all 10000+ agents: PositionX/Y, SpeedX/Y, States, JobType, JobId, StuckTimer, WorkProgress, CellStay, CarriedItem/Count, NextInSpatialCell, WaypointX/Y/Count/Index, Hunger/Sleep/Fatigue/EnvironmentSatisfaction/Mood/NeedsBehavior/NeedsRetryTimer. Zero objects allocated per-agent. Mutated exclusively in simulation thread.

### src/simulation/agents/AgentMovementService.cs
Per-agent movement logic: MoveTowards(targetX,targetY,reachedCB), IsTileBlocked(x,y), MoveToPoint(position, reachedCB), EjectFromWall, PushAway, Fatigue slowdown x0.85 when >80%. Uses AgentSpatialGrid for collision, HierarchicalPathfinder for waypoints, FlowFieldManager for local detours. Calls request path if distance >= 4 tiles.

### src/simulation/agents/AgentSpatialGrid.cs
Spatial hash grid: O(1) proximity queries. Cells keyed by floor(pos / CellSize). Double-buffered: rebuild every ~12 ticks (configurable). Insert/Delete under lock. Read-only during worker phases. Used by Overcrowd checks, StandValidation, PushAway, AgentMovementService neighbor lookup.

### src/simulation/agents/AgentState.cs
Enum: Idle, Moving, Working, Carrying, Returning, Waiting, SeekingFood, Resting, Migrating, Evacuating. Determines behavior in Bookkeep, Speed modifiers, Dispatcher filtering.

### src/simulation/agents/FlowFieldManager.cs
Local detour BFS on 33×33 window (max 100 steps). ThreadLocal scratch buffers. Returns direction vector avoiding walls/trees/other agents. Early exit ≤5 tiles (no BFS needed). Calculated in Phase3a bookkeeping loop. Previously had GameProfiler scope removed (contention fix).

### src/simulation/agents/IdleWorkerSpatialGrid.cs
Separate spatial grid tracking idle workers only. Used by Dispatcher CollectIdle for quick assignment. Striped 32-shard locks instead of global lock. Updates BookKeepSingleAgent's UpdateWorkerChunk calls.

### src/simulation/agents/AgentDataPool.cs
SoA agent pool: all position/state/job data in flat parallel arrays (float[], int[], byte[], etc.). Zero-object allocation model. Authoritative source during simulation. Committed back to renderers via snapshot queues.

### src/simulation/pathfinding/HierarchicalPathfinder.cs
Hierarchical A* pathfinding: coarse regions (16×16) + fine window (3×3 windows), B-Smooth Bresenham smoothing post-A*, cached paths in ConcurrentDictionary. Build graph once at start, invalidate when walls change. Used by AgentMovementService when waypoints requested ≥4 tiles away. Heavy work item (kind: WorkKind.Heavy). Optimizations: ArrayPool/T-stack allocations, ThreadLocal scratch buffers replacing List<> allocations.

### src/simulation/offline/OfflineCatchUpPolicy.cs

### src/simulation/offline/OfflineAgentNeeds.cs

### src/simulation/offline/OfflineCropGrowth.cs

### src/simulation/offline/OfflineWorldTicker.cs

### src/simulation/simd/SimdNeedsBatch.cs

### src/ui/renderers/ShadowCasterRenderer.cs

### src/ui/renderers/ItemShadowRenderer.cs
Unified shadow renderer for ground items, crops, and stockpile items: single MultiMesh buffer aggregates all shadow quads. SetSun(sun) called each _Process. Reduces draw calls by combining multiple item shadow sources.

===============================================================================
КЛЮЧЕВЫЕ АРХИТЕКТУРНЫЕ РЕШЕНИЯ
===============================================================================

1. SOA Pattern (Structure of Arrays): All agent data stored in flat parallel
   arrays (float[] PositionX, float[] PositionY, etc.) instead of individual
   objects. Zero GC pressure, maximum L1/L2 cache hit rate. Implemented in
   AgentDataPool, used by all worker-phase methods.

2. Dedicated Simulation Thread: Task.Run isolates simulation from main thread.
   Fixed timestep 0.05s prevents spiral of death (max 5 substeps). Communication
   via ConcurrentQueue (snapshots), volatile fields (GameTimeSeconds),
   CallDeferred (events to main thread). NEVER calls Godot Node methods from
   simulation thread.

3. GPU Instancing: All mass-rendered entities use MultiMeshInstance2D with
   CustomAABB=(32768,32768,1000). Agents, items, crops, crops, designations,
   zone markers all batched into single draw calls per type.

4. Space Chunking: 512×512 map divided into 32×32 chunks of 16×16 tiles each.
   Used by JobBroker (spatial indexing for targets), GroundItemManager,
   StockpileManager for O(k) rather than O(n) proximity queries.

5. Lock-Free Where Possible: Interlocked/Atomic operations for counters,
   CAS for job claiming, volatile for shared state. Locks only where strictly
   necessary (manager internal dictionaries).

6. Event Marshalling: All manager events that affect UI/renderers MUST marshal
   to main thread via Callable.From(()=>Event?.Invoke(...)).CallDeferred().
   Internal state protected by lock(_lock).

7. Time Scaling: Speed *max(1, speed/16) scaling for dispatch/growth intervals
   prevents call frequency explosion at high speeds (100x ≈ 56 dispatch calls/s
   instead of 333). Sleep(1) for cold iterations at speed>=25 prevents busy-loop.
